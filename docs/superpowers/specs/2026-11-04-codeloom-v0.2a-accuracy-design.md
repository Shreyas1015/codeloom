# codeloom v0.2a — map accuracy (design)

Date: 2026-11-04 · Status: approved by the author in brainstorming · Builds on v0.1.0 (tag `v0.1.0`).

v0.2 is split in two plans (author decision): **v0.2a map accuracy** (this document), then **v0.2b tours and
progress** (separate design). v0.2a makes the map better before tours are built on it.

## Goal

Close the accuracy gaps found in v0.1 and in the real-app acceptance runs, without ever adding a wrong
`exact` link (precision first, unchanged from the v0.1 spec §7a).

## Scope

### 1. Method nodes and method → method call edges in `graph.json`

- The indexer adds a node per class method (and per object-literal method the code index already names):
  `type: "function"`, `id: function:<file>:<Class.method>`, `name: <Class.method>`, `filePath`, `lineRange`,
  `summary: ""`, `tags: ["method"]`, `complexity` from line count (same rule as functions). A `contains` edge
  links the file node to it (and the class node to it when the class node exists).
- `calls` edges come from the linker's code index + call resolver: one edge per (caller symbol → callee
  symbol) pair that resolves with confidence `exact` or `param` (never `guess`), across functions and methods,
  within a repo. Each edge carries `description: "exact" | "param"` (the UA edge field) and `weight` 1 for
  exact, 0.6 for param. Duplicate pairs collapse to the best confidence.
- Still the Understand Anything `KnowledgeGraph` format; existing node ids are unchanged; output stays
  deterministic (nodes and edges sorted as today). CACHE_FORMAT bump.
- Effects: the inspector's "Called by / Calls" (dashboard) and `get_node` / `get_neighbors` / `explain_context`
  (MCP) show service calls; the Map's file cards list methods. The inspector's "not mapped yet" note is
  removed once a stop's `ref` is an exact method node.
- Chain stops get the method node id as `nodeId` when it exists (today they fall back to the class/file node).

### 2. More UI calls reach their page

Patterns the UI reverse walk follows (confidence ≤ `param`; anything not resolvable stays unresolved):
- a function passed as a plain call argument (`useMutation(saveCustomer)`, `onSuccess: refresh` in an object
  argument, `array.forEach(handle)` is excluded — only when the callee is an imported/local function or a
  known hook-like (`use*`) call);
- hooks that return an array (`const [save, state] = useSave()` with `return [save, state]`);
- nested destructuring (`const { form: { submit } } = useForm()`);
- namespaced hooks (`hooks.useX()`, `import * as hooks`);
- HTTP clients re-exported through barrel/index files and namespace imports;
- the line of an inline arrow handler returned by a hook is used for its stop (v0.1 known limit).

### 3. Other-service calls and route ties

- A UI call whose base (env var / host) is not the `apiBase` of any workspace repo is an **external-service
  call**: listed in `check` under its own group "Calls to other services (N)" with the base name, not counted as
  `ui-no-route` or broken. Optional names in `codeloom.workspace.json`:
  `external: [{ "name": "Payments", "apiBase": ["PAYMENTS_URL"] }]` (validated; unknown keys rejected as today).
- Route ties: when a call path matches two routes at equal rank and one route has a literal segment equal to the
  call's literal segment at that position, the literal route wins at `param`; a real tie stays `guess`.

### 4. Redux, class components, Mongoose

- Redux: `dispatch(thunkCreator(args))` → the thunk; `createAsyncThunk("x", payloadCreator)` → the payload
  creator; RTK Query `builder.query/mutation({ query: … })` endpoints → an HTTP call when the `query` returns a
  readable url (with the API slice's `baseUrl`). Confidence ≤ `param`.
- Class components: lifecycle methods (`componentDidMount`, `componentDidUpdate`, …) and handlers bound in the
  class (`this.handleX`, `onClick={this.handleX}`) are reached from the class's page; `this.props.onX()` is
  followed only when the prop is passed a resolvable function at the JSX call site.
- Mongoose: `new Model(data).save()`, `connection.model("Name", schema)`, CommonJS
  `module.exports = mongoose.model(...)` and `exports.X = mongoose.model(...)`.

## Out of scope (v0.2b or later)

Tours, progress, new MCP tools, new dashboard screens; non-JS languages for journeys; GraphQL/tRPC.

## Testing and acceptance

- Every pattern: a unit test on generic demo-shop-style code (Customer/Invoice; never work code).
- Eval gate stays 100% precision/recall; answer keys are never edited. realworld (class components + Redux)
  should gain page reach; record the before/after in `fixtures/evals/README.md`.
- graph.json determinism (warm/cold re-index byte-identical) and a size note (before/after on demo-shop and the
  eval apps).
- Acceptance re-run on the author's local workspace copy (same privacy rules as v0.1 Task 5), compared with
  v0.1 run 3: UI calls with no page, routes with a UI caller, other-service calls separated, inspector "Calls"
  filled for service methods, no new wrong `exact` links.
