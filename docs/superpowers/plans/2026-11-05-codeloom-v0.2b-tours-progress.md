# codeloom v0.2b — tours and progress — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. UI tasks also use the `impeccable` skill (craft floor before UI edits).

**Goal:** Implement `docs/superpowers/specs/2026-11-05-codeloom-v0.2b-tours-progress-design.md`: tours (committed `.codeloom/tours/<journeyId>.json`, written by the agent through MCP), personal progress (`~/.codeloom/progress/<workspaceId>.json`: seen → toured → understood, re-walk on code change), MCP tools `build_tour_context` / `save_tour` / `get_progress` / `record_check`, prompts `write-tour` / `check-me`, and the dashboard's Tour mode and Progress screens plus the progress parts of Home and Journey.

**Architecture:** New store modules for tours and progress (zod schemas, atomic writes, deterministic sorting; progress lives under `CODELOOM_HOME` or `~/.codeloom`). MCP tools are thin wrappers over those modules; codeloom (never the agent) computes file hashes and commits. The dashboard server gains read endpoints and the only two write endpoints (`seen`, `toured`); the watcher adds `tours`/`progress` change keys. Two new screens follow the approved mocks (screens 3 and 5) and `DESIGN.md`.

**Tech Stack:** existing (TypeScript, zod 4, MCP SDK, Node http server, React/Vite/TanStack/shadcn, Shiki, Playwright).

### Task 1: Tour and progress store (spec §1, §2)
- `packages/cli/src/store/tours.ts`: `TourFileSchema` (spec §1 shape, `version: 1`, exactly 3 check questions, size caps), `readTour(root, journeyId)`, `writeTour(root, journeyId, draft, ctx)` that computes `stops[].fileHash` (sha256 of the stop file's current content) and `writtenAtCommit` per repo (git HEAD) and writes atomically to `<root>/.codeloom/tours/<journeyId>.json` (sorted keys/arrays), `tourStaleStops(tour, ws)` (stops whose current hash differs), `listTours(root)`.
- `packages/cli/src/store/progress.ts`: `ProgressFileSchema` (spec §2), `workspaceId(ws)` (sha256 of workspace name + sorted repo ids, first 16 hex), `progressPath(ws)` (`$CODELOOM_HOME/progress/<id>.json` else `~/.codeloom/...`), `readProgress`, and mutators `markSeen(ws, journeyId)`, `markToured(ws, journeyId, phases)` (requires all four phases), `recordCheck(ws, journeyId, { questions, answers, verdict, notes })` (appends; on `pass` sets `understoodAt`, `understoodAtCommit`, `stopHashes` computed from the journey's current stops), `progressView(ws, state)` → per journey `{ level: "none"|"seen"|"toured"|"understood", needsReWalk: stopKey[], lastCheck }` + totals per repo/area. Corrupt file → clear CodeloomError (exit 2), never overwritten.
- Uses the shared `stopKey` (move it from the dashboard's `lib/journey-stops.ts` into a cli module the dashboard imports type-safely, or duplicate with a cross-check test — choose and document).
- `codeloom doctor` checks the progress file (valid / corrupt) and tours (valid, stale stops count).
- Tests: schemas; hashing; workspaceId stability (same id for a clone at another path); `markToured` needs all four phases; `recordCheck` fail never sets understood; pass sets it; editing a stop file → `needsReWalk` lists exactly that stop; CODELOOM_HOME respected; corrupt file error.

### Task 2: MCP tools and prompts (spec §1, §2)
- `build_tour_context { journey }` (code slices ± 30 lines, types, db/SQL detail, request/response shapes found in code, neighbors via method edges, current hashes; < 1 MB with the cap helper), `save_tour { journey, tour }` (validates against the journey's stops; never trusts agent hashes), `get_progress { repo?, area? }`, `record_check { journey, questions, answers, verdict, notes }`.
- Prompts `write-tour { journey }` and `check-me { journey }` per the spec text (plain, short; check-me asks one question at a time, judges against code + expected points, never records an unearned pass; uses tour questions or writes 3 from code).
- Update the MCP catalogue/contract tests (`test/mcp-catalogue.ts`, `mcp-contract.test.ts`), README MCP table, docs test.

### Task 3: Server endpoints and live updates (spec §3)
- `GET /api/progress` (progressView + totals), `GET /api/tours/:journeyId` (tour + stale stops), `POST /api/progress/seen { journey }`, `POST /api/progress/toured { journey, phases }` — JSON bodies ≤ 16 KB, validated; 405 for other methods; same auth/Host/cookie rules; still no other writes. `api-types.ts` updated.
- `watchMap` adds change keys `tours` (workspace `.codeloom/tours/`) and `progress` (the progress file's folder); dashboard invalidation map updated (tours → tour/*, journey/*; progress → progress, overview, journeys).
- Tests: auth on POST, body validation, "understood" can't be set via HTTP, watcher keys, invalidation.

### Task 4: Tour mode screen (spec §3, mock screen 3)
