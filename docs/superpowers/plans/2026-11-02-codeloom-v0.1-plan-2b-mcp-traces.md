# codeloom v0.1 — Plan 2b: MCP server, journey tools, and trace check — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Claude (or any MCP agent) the codeloom map — read tools, journey tools, `check_chains`, two prompts — via `codeloom serve`; register it in `.mcp.json` on `init`; add the optional runtime check `codeloom check --traces` (OTLP file or Grafana Tempo).

**Architecture:** A stdio MCP server (`@modelcontextprotocol/sdk` `McpServer`) whose tools read the same committed files Plan 2a writes (`graph.json`, `endpoints.json`, `chains.json`, `journeys.json`) fresh on every call, and write only through `store/json.ts` (`journeys.json`, new `summaries.json`). Trace checking is a separate module (`check/traces/*`) that turns OTLP spans into normalised spans and compares them with `chains.json`; Tempo is the single network call in the package and is opt-in.

**Tech Stack:** TypeScript (ESM, Node ≥ 20), `@modelcontextprotocol/sdk` 1.32.x (zod peer `^3.25 || ^4.0`, so our zod 4 works), zod 4, commander 12, vitest 3, `@codeloom/core` (`SearchEngine`, `KnowledgeGraph`). Tests: SDK `Client` + `InMemoryTransport.createLinkedPair()`; recorded OTLP JSON; a stubbed `fetch` for Tempo.

**Spec:** `docs/superpowers/specs/2026-10-30-codeloom-design.md` §2 (CLI), §4 (data files), §5 (MCP tools and prompts), §7a.1/§7a.4/§7a.5 (check, traces, spot-check), §8 (testing). **Memo:** `.superpowers/sdd/plan2-design-memo.md` (k) MCP and (l) OTel.

## Global Constraints

Everything in `.superpowers/sdd/2a/global-constraints.md` still binds (package/CLI names, Node ≥ 20 ESM with `.js` relative imports, every written JSON file has `"version"`, zod-validated on read, atomic writes via `store/json.ts`, bad files reported never overwritten, `packages/core` untouched, no work content, deterministic committed files sorted with `util.compare`, exit codes 0/1/2, confidence vocabulary `exact|param|guess`, ask before push/publish). Amended and added for Plan 2b:

- **Network:** the package makes exactly one kind of network call: `codeloom check --traces` (and `check_chains` with `traces: true`) to the user's own Tempo URL from `codeloom.workspace.json` → `traces`. Opt-in, 10 s timeout, never at import time, never in `index`/`serve` startup. No telemetry. Tests never touch the network (stub `fetch`).
- **No AI in codeloom.** The MCP server only reads and writes the map; prompts are text templates the agent runs.
- **MCP logging goes to stderr only.** Nothing but MCP protocol frames may be written to stdout while `serve` runs (no `console.log` in any code path reachable from a tool).
- **Fresh reads.** Tools read files on every call (no cache across calls), so agent writes and post-commit re-indexes show up immediately (spec §2: "MCP and the dashboard share one store").
- **Write rules (spec §5):** write tools go through the store and its zod validation; invalid input returns a tool error (`isError: true`) with a clear message and changes nothing. MCP tools never write `chains.json`, `graph.json` or `endpoints.json` (only `reindex` regenerates them, by running the indexer).
- **Node references** across the workspace: object `{ repo, nodeId }`, string form `repo::nodeId` (memo (k)). Every tool that takes a node accepts the string form.
- **Tool output:** every tool returns one `text` content item holding pretty JSON (`JSON.stringify(x, null, 2)`) of a documented result object, and the same object as `structuredContent`. Lists are sorted deterministically and capped (documented `limit`, default and max per tool); a capped list says so with `truncated: true`.
- **`summaries.json`** is a new committed per-repo file (`<repo>/.codeloom/summaries.json`), `{ version: 1, summaries: Record<nodeId, string> }`, keys sorted with `compare`, written with `writeJsonIfChanged`. Written only by `save_summary`.
- **Trace headers** come from the environment variable named by `traces.headersEnv` (OTEL convention `key1=value1,key2=value2`), never from a file. Never print header values.

import type { CallToolResult } from "@modelcontextprotocol/sdk/types.js";
/** Success: one text item with pretty JSON + structuredContent (the same object). */
export function ok(result: Record<string, unknown>): CallToolResult;
/** Failure: isError true, one text item with the message. CodeloomError → its message; ZodError →
 * "Invalid input: <path>: <message>; …"; anything else → "Unexpected error: <message>". */
export function fail(err: unknown): CallToolResult;
/** Wrap a tool handler: returns ok(await fn(args)) or fail(err). Never throws. */
export function withErrors<A>(fn: (args: A) => Promise<Record<string, unknown>> | Record<string, unknown>): (args: A) => Promise<CallToolResult>;

// ---- mcp/state.ts -----------------------------------------------------------------------------
import type { WorkspaceData, RepoData } from "../store/read.js";
export interface MapState {
  ws: WorkspaceData;                 // loadWorkspaceData(start) — throws dataError (exit 2) when not indexed
  chains: Chain[];                   // [] when chains.json is missing
  uiReach: UiReachFact[];            // chainsFile.uiReach ?? []
  manualLinks: ManualLinkStatus[];   // chainsFile.manualLinks ?? []
  journeys: Journey[];               // [] when journeys.json is missing

}

export function formatNodeRef(r: NodeRef): string;          // `${repo}::${nodeId}`
export function findNode(state: MapState, ref: NodeRef): { repo: RepoData; node: GraphNode };  // unknown repo/node → dataError naming it
export function chainsTouchingNode(state: MapState, ref: NodeRef): Chain[];   // stops with that repo+nodeId, or repo+file when the node is a file node; sorted by id
export function journeysForChains(state: MapState, chainIds: Set<string>): Journey[];  // sorted by id

export interface ServerOptions {

}
export function createServer(opts: ServerOptions): McpServer;   // name "codeloom", version VERSION

export function registerCheckTools(server: McpServer, opts: ServerOptions): void;       // tools/check.ts
export function registerPrompts(server: McpServer, opts: ServerOptions): void;          // prompts.ts

// ---- store/summaries.ts -----------------------------------------------------------------------
export const SummariesFileSchema = z.object({ version: z.literal(1), summaries: z.record(z.string(), z.string()) });  // in schemas.ts
export function readSummaries(repoAbs: string): Record<string, string>;          // missing → {}
export function writeSummary(repoAbs: string, nodeId: string, text: string): boolean;  // sorted keys, writeJsonIfChanged; empty text deletes the key

// ---- store/journeys-edit.ts -------------------------------------------------------------------
export type JourneyOp =
  | { op: "create"; name: string; area?: string; note?: string; chainIds: string[] }
  | { op: "update"; id: string; name?: string; area?: string; note?: string }      // rename / re-area / note
  | { op: "merge"; ids: string[]; name: string; area?: string; note?: string }      // ≥2 ids → one journey, chainIds = sorted union
  | { op: "split"; id: string; parts: Array<{ name: string; area?: string; note?: string; chainIds: string[] }> }  // ≥2 parts, each non-empty subset of the journey's chainIds, together covering all of them, no overlap
  | { op: "delete"; id: string };
export interface JourneyOpsResult { journeys: Journey[]; created: string[]; updated: string[]; deleted: string[] }
/** Pure. Applies ops in order to a copy. New ids = journeyId(sorted chainIds) (chains.ts). Unknown chain ids
 * (not in knownChainIds), unknown journey ids, a new id that already exists, empty name, or a bad split →
 * dataError naming the op index ("ops[2]: …"); no partial result. area/note default "". status of new = "ok".
 * Output journeys sorted by id. */
export function applyJourneyOps(journeys: Journey[], ops: JourneyOp[], knownChainIds: Set<string>): JourneyOpsResult;
/** Read journeys.json fresh (handWritten), apply, validate with JourneysFileSchema, writeJsonAtomic. */
export function saveJourneys(state: MapState, ops: JourneyOp[]): JourneyOpsResult;

/** range undefined → working tree vs HEAD (staged + unstaged) plus untracked files; "base..head" or "base" → git diff base..head. */
export function changedLines(repoAbs: string, range?: string): ChangedFile[];   // sorted by file; bad range → dataError

export function spansFromOtlp(doc: unknown): TraceSpan[];

export function readOtlpFile(path: string): TraceSpan[];

export async function fetchTempoSpans(cfg: Extract<TracesConfig, { kind: "tempo" }>, opts?: TempoOptions): Promise<TraceSpan[]>;  // network/HTTP errors → throws TraceSourceError

export async function runTraces(ws: WorkspaceData, chains: Chain[], opts: BuildReportOptions): Promise<TracesReport | TracesSkipped>;

export function ensureMcpEntry(root: string): McpFileResult;

Order: 1 → 12. Each task: TDD, run `pnpm --filter codeloom test <file>` + `pnpm --filter codeloom typecheck`, commit with a message ending `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.

Each task below is a requirements brief (as in the Plan 2a hardening plan): the implementer writes failing tests for every listed case first, then the code, coding against the Interfaces Registry above. Exact names, shapes and messages in the registry and catalogue are binding.

### Task 1: MCP skeleton, `codeloom serve`, shared state and results
Requirement summary: add the SDK dependency (`pnpm --filter codeloom add @modelcontextprotocol/sdk@^1.32.2`); `mcp/result.ts`, `mcp/state.ts`, `mcp/server.ts` (registers whatever registrars exist so far; later tasks add theirs to `createServer`), `commands/serve.ts`, `serve` command in `cli.ts`; first tool `workspace_overview`. Tests over `InMemoryTransport.createLinkedPair()` with SDK `Client`: tools/list contains `workspace_overview`; overview on demo-shop (materializeFixture + runIndex) returns 3 repos with counts > 0; an un-indexed folder returns `isError` with the "Run \"codeloom index\" first" message; `parseNodeRef` cases; a test asserting `runServe`'s module path never writes to stdout during a tool call (spy on `process.stdout.write`).

### Task 2: `index_status`, `reindex`, `get_layers`
Requirement summary: per catalogue. `index_status` needs the fingerprints `gitCommitHash` (read `fingerprints.json` with `FingerprintsSchema`; missing → null) and `git diff --name-only <indexed>..HEAD` + `git status --porcelain` filtered to files that `listFiles` would index. `reindex` calls `opts.reindex ?? runIndex`. Tests: fresh index → `stale: false`; commit a change → `stale: true` with that file; untracked new `.ts` file → stale; `reindex` then `stale: false`; `get_layers` with and without `repo`, unknown repo → isError.

### Task 3: Summaries + `search`, `get_node`, `get_neighbors`, `explain_context`, `save_summary`
Requirement summary: `store/summaries.ts` + schema + `FILES.summaries`; tools per catalogue in `mcp/tools/graph.ts`. Tests on demo-shop: search "customer" finds a function node and the `/customers` page and the `customers` table; `kinds` filter; get_node on a handler shows its chains and journeys (create a journey via `saveJourneys` fixture data or write journeys.json directly); neighbors depth 2 deterministic; explain_context cuts at maxChars with `truncated: true`; save_summary writes sorted, idempotent (second save → `saved: false`), empty text removes; invalid node ref → isError, file untouched.

### Task 4: Journey tools — `list_chains`, `get_journey`, `trace_route`, `save_journeys`
Requirement summary: `store/journeys-edit.ts` (pure `applyJourneyOps` + `saveJourneys`) and `mcp/tools/journeys.ts`. Tests: applyJourneyOps unit tests for every op incl. each error (unknown chain, duplicate id, bad split overlap/uncovered, merge < 2, empty name) leaving input untouched; list_chains filters + paging + `unnamed`; get_journey by journey id and by chain id, lanes deduped; trace_route by "POST /api/customers", by "/api/customers/{id}" (normalised), by "table:customers", by node ref; save_journeys over MCP writes journeys.json that `JourneysFileSchema` accepts and that a following `codeloom index` keeps (status untouched, byte-identical except status flips).

### Task 5: `check_chains` + `impact_of_diff`
Requirement summary: refactor `commands/check.ts` into `buildReport` (async) + `runCheck` (async; cli action awaits; exit codes unchanged); `check_chains` returns the same `CheckReport` as `codeloom check --json` (test deep-equality); `workspace/diff.ts` `changedLines` via `git diff -U0 --no-color` hunk headers (`@@ -a,b +c,d @@` → [c, c+d-1], d=0 → deletion at c → [c,c]) plus untracked (`git ls-files --others --exclude-standard`) as "all"; `impact_of_diff` maps changed lines to graph nodes whose lineRange overlaps (file nodes when "all"), chains with a stop in a changed file whose line falls in a changed range (or any stop in an "all" file), journeys containing them, tables/queues of those chains. Tests: edit the customers controller method body → its chains/journeys/tables listed; untracked file → listed as "all"; `range` between two commits; bad range → isError.

### Task 6: Prompts `name-journeys`, `verify-journey`
