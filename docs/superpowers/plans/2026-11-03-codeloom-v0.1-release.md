# codeloom v0.1 — Release plan — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A published-ready `codeloom` npm package that installs fast with no native build step, carries the core engine, the grammars and the dashboard inside it, is documented, proven by a tarball install test in CI, and has passed the v0.1 acceptance run on the author's real workspace — then (only with the author's approval) published to npm and the GitHub repo made public.

**Architecture:** Only `packages/cli` is published (spec §2). A release build bundles the cli's own code and the private `@codeloom/core` source into `packages/cli/dist` with esbuild (npm dependencies stay external), copies every tree-sitter grammar `.wasm` file into `dist/grammars/` (so no `tree-sitter-*` npm package — each runs `node-gyp` on install — is a runtime dependency), and copies the built dashboard into `dist/dashboard/` (where `locateDashboardAssets` already looks). `npm pack` of `packages/cli` is then installed into a clean temp folder in CI and exercised end to end.

**Tech Stack:** esbuild (bundling), Node ≥ 20 ESM, pnpm 11 workspace, GitHub Actions, npm.

**Spec:** `docs/superpowers/specs/2026-10-30-codeloom-design.md` §2 (packaging: "Only `packages/cli` is published; `core` and the built dashboard are bundled into it"), §7 acceptance criteria 1–7 (esp. 3: real workspace; 6: "CI green; tarball installs and runs; UA notice included. npm publish only after the author approves").

### Task 1: Grammar files resolve from the package, not from native npm packages
- `grammarPath(pkg, file)`: look for `<dir of the bundled entry>/grammars/<file>` (the release layout puts the bundle at `dist/bin.js` and grammars at `dist/grammars/`; resolve relative to `import.meta.url` of the module that defines it, so it works both bundled and unbundled), else fall back to `createRequire(import.meta.url).resolve(\`${pkg}/${file}\`)` (dev/monorepo). Used for every grammar `.wasm` in `tree-sitter-plugin.ts` (incl. the TS/TSX/JS special cases). web-tree-sitter's own runtime wasm stays resolved by web-tree-sitter.
- `scripts/release/collect-grammars.mjs <outDir>`: reads the language configs' `wasmPackage`/`wasmFile` (import them from core's built `dist/languages`), plus `tree-sitter-tsx.wasm`; copies each `.wasm` into `<outDir>` and the package's `LICENSE`/`LICENSE.md`/`COPYING` (first found) into `<outDir>/LICENSES/<package>.txt`; exits 1 naming any missing file.
- Update `NOTICE`: one line "packages/core modified: grammar file resolution (grammar-path.ts)".
- Tests: `grammarPath` prefers a bundled file when present (temp dir layout), falls back to resolve otherwise; collect-grammars on the real workspace produces every expected file + licence; an index of demo-shop still parses TS/JS (existing tests).

Remove stale tsc output that is not needed at runtime from the packed set via `files` (not by deleting — tests still use tsc output).
  - Decide and document: the published `files` = `["dist/bin.js", "dist/bin.js.map", "dist/grammars", "dist/dashboard", "README.md", "LICENSE", "NOTICE", "CHANGELOG.md"]` (the tsc per-file output and `.d.ts` are not shipped; codeloom has no public JS API in v0.1). If anything at runtime imports a non-bundled relative file, the pack test (Task 3) must catch it.
- `packages/cli/package.json`: `version: "0.1.0"`, `description`, `keywords` (code map, user journeys, mcp, claude, codebase, onboarding), `repository` (`git+https://github.com/Shreyas1015/codeloom.git`, `directory: packages/cli`), `homepage`, `bugs`, `author: "Shreyas1015"`, `license: "MIT"`, `files` as above, `engines: {node: ">=20"}`, `publishConfig: {access: "public"}`; `dependencies` = every npm package the bundle imports at runtime (cli's own + core's: `web-tree-sitter`, `fuse.js`, `yaml`, `ignore`, `zod`, `@modelcontextprotocol/sdk`, `commander`, `typescript`) and **no** `tree-sitter-*` grammar packages, no `@codeloom/*`; `@codeloom/core` moves to `devDependencies`. `prepack`: fails with a clear message unless `dist/bin.js`, `dist/grammars`, `dist/dashboard` exist (i.e. `pnpm release:build` ran).

### Task 3: Tarball install test (local + CI)
- `scripts/release/pack-test.sh`: `pnpm release:build` → `cd packages/cli && npm pack --pack-destination <tmp>` → new temp dir, `npm init -y`, `npm install <tarball>` (no workspace, no pnpm) → `node scripts/release/no-native-deps.mjs <tmp>/node_modules` → copy `fixtures/demo-shop` to a temp workspace and git-init each repo (as `materializeFixture` does) → run the installed `npx codeloom`: `--version` (= 0.1.0), `init`, `index`, `check` (exit 0, summary line present), `doctor` (exit 0 or 1 with no errors besides allowed warnings), `check --json | node -e` validate, `dashboard --no-open --port 0`-equivalent (start in background, read the printed URL, `curl` the URL with the token, then `/api/overview` with the cookie → 200 JSON with 3 repos; kill), `serve` (a tiny node script using the installed `@modelcontextprotocol/sdk` client over stdio lists tools = the 15 names and calls `workspace_overview`).
- Also assert the tarball contains `LICENSE`, `NOTICE`, `dist/grammars/LICENSES/*` and has no `src/`, `test/`, `.map` beyond `bin.js.map`; print tarball size (budget: < 5 MB packed, < 35 MB unpacked — grammars are ~25 MB; report actual).
- CI: new `package` job (needs nothing else) matrix Node 20/22 × ubuntu/macOS: pnpm setup on Node 22 (pnpm 11), install, `pnpm release:build`, switch to matrix Node, run `pack-test.sh` (the npm install step uses the matrix Node's npm).
- Local run must pass before the task is done; report output.
