# codeloom 0.5 — one-step setup, Claude-checked PR reviews, proxies — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Implement `docs/superpowers/specs/2026-11-16-codeloom-0.5-checked-pr-reviews-design.md`.

**Architecture:** `codeloom init` becomes a guided wizard (node:readline, no new deps) with a shared headless
Claude runner. `codeloom review` gets a new default layout built from facts (writes vs reads, risks,
changed-path diagram) and a `--repo` mode for folders of repos. A capped "check packet" + `check-pr` prompt
+ validated `save_pr_review` tool let Claude check and correct the draft cheaply; a saved review renders as
"Checked by Claude". The linker follows workspace `proxies` from a UI repo's prefix into another repo.

**Tech Stack:** TypeScript (Node ≥ 20), commander, zod, vitest 4, MCP SDK.

  yes (or passes `--check` / `--yes`-equivalent flags documented in the spec). Without `claude` on PATH, print

- Packet cap **24,000 characters**; hunks ≤ 60 lines each, ≤ 400 total; commit text ≤ 40 lines; cuts listed.

- `save_pr_review`: `head` must equal HEAD; every function/route/table/queue named must exist in the packet's
  facts, else refused listing the bad names; saved to `<ws>/.codeloom/reviews/<head>.json`, never committed.
- Every label escaped as in 0.4 (markdown + Mermaid + marker neutralising); `codeloom.workspace.json` always
  has `links: []`.
- Docs contract: every new command, flag, MCP tool and prompt in `docs/reference.md` (docs test); README gets
  the one-step setup in Quick start.
- Tests in `packages/cli/test` (TDD: failing test first). CLI tests already get a git identity from
